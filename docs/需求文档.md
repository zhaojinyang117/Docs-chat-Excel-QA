# **AI 文档聊天 & Excel QA**

**1\. 项目目标**

* 实现一个用户友好的 Web/命令行界面，用户能上传文档或 Excel 文件并与其对话。

* 文档聊天：支持全文本索引、分段向量化、检索增强生成回答（RAG），并返回相关段落来源。

* Excel QA：能解析 Excel（多 sheet、表头、合并单元格），进行结构化理解并回答自然语言问题，支持定位到具体单元格/行/列并展示原始数据片段。

* 可运行在本地/云端（给出部署说明）。

**2\. 主要功能（功能列表）**

1. 用户管理（可选）：简单用户名登录（课堂演示可跳过）。

2. 文档上传：支持 PDF、DOCX、TXT，自动抽取文本并分段。

3. Excel 上传与解析：支持 .xlsx，自动解析表头、数据类型、日期/数值识别、合并单元格处理。

4. 向量化与索引：

   * 文档段落向量化（使用句嵌入/模型）。

   * Excel 行/表格段落化并向量化（每行或每个表格片段作为文档段）。

   * 本地向量库（FAISS 或 简易 sqlite \+ vector）或内存索引。

5. 查询接口：

   * 聊天式对话（维护上下文短期历史）。

   * Excel QA：当用户指定目标为某个上传的 Excel 文件时，优先在表格索引中检索。

6. 回答生成：结合检索结果调用大模型生成最终回答；同时返回来源片段与置信度（或相关性得分）。

7. 来源定位：在回答中标注来源文件名、sheet 名称、行号或段落编号，并提供原文片段或高亮。

8. 日志和审计：记录用户提问、检索来源、回答（便于评分）。

9. UI（可选）：

   * Web 前端（Flask/FastAPI \+ 简单 HTML/JS），或

   * 命令行交互（简单演示版本）。

**3\. 用户故事（示例）**

* 学生 A 上传公司报告 PDF，问：“这份报告里关于市场份额的结论是什么？”系统返回摘要并显示对应段落与页码。

* 学生 B 上传 sales.xlsx，问：“2024 年 Q1 哪个产品的销售额最高？”系统返回产品名、数值、所在 sheet 与行号，并可展示该行数据。

* 学生 C 在对话中追问：“那去年同期是多少？”系统使用会话上下文从 Excel 中检索并比较两行数据。

**4\. 功能需求（详细）**

**4.1 文档处理**

* 支持 PDF（按页抽取文本）、DOCX（保留段落）、TXT（直接读取）。

* 文本预处理：去除空行、合并短句、分段（每段 200–500 字或按语义分割）。

* 每段要保留元信息（文件名、页码、段号）。

**4.2 Excel 解析**

* 读取所有 sheet，检测表头（自动识别首行或多级表头）。

* 将每一行构建为“行段落”：包含 sheet 名、行号、列名-值对的自然语言描述（例如 "产品: A, 年份: 2024, 销售额: 12345"）。

* 支持按列类型（数值/日期/文本）做简单汇总查询（如 sum/avg/max/min）。

**4.3 向量化与索引**

* 嵌入模型（可选）：使用开源模型（sentence-transformers）或商业 API（OpenAI Embeddings）；

* 索引选择：FAISS（建议）或简单 in-memory list \+ cosine（小数据集可用）。

* 支持批量插入与检索 Top-k。

**4.4 检索与生成（RAG）**

* Query → 检索 Top-K 段 → 用模板把检索到的段传给 LLM 生成回答（并把来源插入回答脚注）。

* 支持把 Excel 优先索引（如果用户指定文件类型为 Excel）。

**4.5 回答可解释性**

* 对回答给出来源列表（文件、sheet、行/页码）和相似度分数。

* 对数值型问题（比如求和、比较）优先使用基于表格的计算（避免 LLM “胡扯”）。

**验收标准（Example）**

* 文档聊天：在 10 条测试问题中，能正确回答并给出正确来源 ≥ 8 条。

* Excel QA：能正确回答 10 条基于表格的数值/定位问题 ≥ 9 条（数值计算必须精确）。

* UI/交互：能上传文件并进行问答，响应时间合理（检索+生成 \< 10s，视模型而定）。

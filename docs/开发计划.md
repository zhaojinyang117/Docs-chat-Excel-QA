# 开发计划

## 0. 总体缝合策略（先说结论）

建议选一个“母项目”做骨架，再按模块往里换/加东西：

* **整体骨架（多文档 + RAG + UI）：**
  👉 `sidduneraki/Multi-Document-RAG-Chatbot`（多文档、多格式、FAISS、Streamlit，一体化比较全）
* **Excel 能力模板（怎么把 Excel 变成 RAG 数据）：**
  👉 `manivarmabekkam/RAG_with_xlsx` + `Kamalesh002/Azure-RAG-XLS-Chatbot` + `Shivvam/rag-excel-local-qwen3`
* **API 化、日志、稍微“工程化”的参考：**
  👉 `varundineshan/RAG-AI-Document-Chat`（FastAPI + 向量库 + 日志结构清晰）

下面我按你之前那 10 个模块，逐个写清楚：**用什么库 + 主要抄哪个仓库 + 怎么缝**。

---

## 1️⃣ 模块1：文件上传 & 预处理

**职责**：收文件、简单校验、存临时目录，调用不同解析器（文本 vs Excel）。

* **主要库**

  * Web 层：

    * 如果先用 Streamlit：`streamlit.file_uploader`
    * 后面要 API 化：`FastAPI` 的 `UploadFile`
* **参考项目**

  * 上传 + 多文档 ingest 流程：`sidduneraki/Multi-Document-RAG-Chatbot`
  * FastAPI 接口形式：`varundineshan/RAG-AI-Document-Chat`
* **缝合方式**

  * 第一版直接**抄 Multi-Document-RAG-Chatbot 里上传+保存文件那段**，包装成 `upload_module.py` 的函数：

    * `save_uploaded_files(files) -> List[FileInfo]`
  * 之后引入 FastAPI 时，把 Streamlit 那块逻辑搬到 FastAPI 的 `POST /upload` 里，**接口不变，调用同一个工具函数**。

---

## 2️⃣ 模块2：文本类文档解析（PDF / DOCX / TXT）

**职责**：把 PDF/DOCX/TXT 变成“带元信息的文本 chunk”。

* **主要库**

  * PDF：`PyPDF2` 或 `pymupdf` / `pdfplumber`
  * DOCX：`python-docx`
  * TXT：原生 `open()` 即可
* **参考项目**

  * 多格式文档解析：`sidduneraki/Multi-Document-RAG-Chatbot`
  * “Chat with PDF” 模式：`ArmaanSeth/ChatPDF`
* **缝合方式**

  * 从 Multi-Document-RAG-Chatbot 里抄**按文件类型选择 loader** 的逻辑，重构成：

    * `parse_text_file(file_path) -> List[Chunk]`
  * Chunk 结构统一设计成：

    ```python
    {
      "text": "...",
      "meta": {
        "file_name": "...",
        "page": 3,
        "chunk_id": "xxx"
      }
    }
    ```

  * PDF 页码提取可以直接抄 `ChatPDF` 里的做法：遍历 page，边读边附上 `page` 字段。

---

## 3️⃣ 模块3：Excel 解析 & 行段落构造

**职责**：把 `.xlsx` 的多 sheet、多表头，变成自然语言行段落 + 元信息。

* **主要库**

  * `pandas` + `openpyxl`
* **参考项目**

  * RAG with Excel 示例：`manivarmabekkam/RAG_with_xlsx`
  * Azure Excel Chatbot：`Kamalesh002/Azure-RAG-XLS-Chatbot`
  * 本地 Qwen + Excel：`Shivvam/rag-excel-local-qwen3`
* **缝合方式**

  * 抄 `RAG_with_xlsx` / `rag-excel-local-qwen3` 中**“遍历 sheet -> DataFrame -> 遍历行”的套路**，封装成：

    ```python
    def parse_excel(file_path) -> List[Chunk]:
        # 每一行生成一个 text + meta
    ```

  * 行描述文本按你的需求做成类似：

    > "文件: sales.xlsx, Sheet: Q1, 行: 5, 产品: A, 年: 2024, 销量: 12345, 地区: 华东"
  * 对**合并表头 / 多级表头**，先用 pandas 填充缺失（`ffill`），再拼进文字。这个处理逻辑可以自己写，比大多开源项目还强。

---

## 4️⃣ 模块4：向量化 & 向量库（FAISS / Chroma）

**职责**：把文本 chunk + Excel 行段落转 Embedding，写入向量库，支持相似度检索。

* **主要库**

  * `langchain` 的 `FAISS` / `Chroma` 封装
  * 或直接用 `faiss` + 自己维护 meta 映射
* **参考项目**

  * Chroma/FAISS + LangChain：`srajal-87/RAG-Multi-Document-Chat-Application`
  * 多文档 + FAISS：`sidduneraki/Multi-Document-RAG-Chatbot`
  * 完全本地 RAG：`curiousily/ragbase`（参考目录组织）
* **缝合方式**

  * 复用 Multi-Document-RAG-Chatbot 中**“documents → embeddings → FAISS index”那一段**，重写成独立模块：

    ```python
    class VectorStore:
        def add_chunks(chunks: List[Chunk]): ...
        def search(query: str, k: int) -> List[Chunk]
    ```

  * 内部调用**后面第7️⃣模块的 `EmbeddingService`**，不要在这里直接写 OpenAI 名字，保证可换 API。

---

## 5️⃣ 模块5：检索 + RAG 生成（核心 QA 流程）

**职责**：接收问题 → 检索文档/Excel 行 → 组 Prompt → 调 LLM → 得到回答。

* **主要库**

  * `langchain.chains.RetrievalQA` / 自己手写 RAG pipeline
* **参考项目**

  * 经典 RAG 流程：`varundineshan/RAG-AI-Document-Chat`
  * 多文档聊天：`sidduneraki/Multi-Document-RAG-Chatbot`
  * 文档 QA Chatbot 模板：`Sargurui/RAG-Based-Document-Q-A-ChatBot`
* **缝合方式**

  * 拿 `RAG-AI-Document-Chat` 的 **“获取问题 → 调 Retriever → 调 LLM → 拼回答”的主流程**，改成调用你自己的：

    * `VectorStore.search(...)`
    * `LLMService.generate(...)`
  * 在这里做一层简单“路由”：

    * 用户指定 Excel 文件：只查 Excel 型 chunks（通过 meta.type == 'excel' 过滤）
    * 否则：文档 + Excel 一起 top-k 检索

---

## 6️⃣ 模块6：来源标注（source attribution）

**职责**：在回答里标出来源：文件 / 页码 / sheet / 行号。

* **主要库**

  * 无需额外库，Python 字符串拼接即可
* **参考项目**

  * 文档来源展示：`varundineshan/RAG-AI-Document-Chat`（回答里尾部列出来源）
  * ChatPDF 类项目：`ArmaanSeth/ChatPDF`（根据 chunk meta 返回页码）
* **缝合方式**

  * 约定每个 `Chunk.meta` 至少有：

    * `file_name`
    * `page`（文档）
    * `sheet`, `row`（Excel）
  * 从 RAG-AI-Document-Chat 抄“把检索结果元信息拼成 citation”的套路，抽成函数：

    ```python
    def build_citations(chunks: List[Chunk]) -> str:
        # 返回像：[1] sales.xlsx Sheet:Q1 行:5; [2] xxx.pdf p.3 ...
    ```

  * 回答时统一格式：

    > 答案正文...
    >
    > 参考来源：
    > [1] …
    > [2] …

---

## 7️⃣ 模块7：模型调用抽象（LLM & Embedding Service）

**职责**：统一封装 OpenAI / Moonshot / 百川 等 API 调用，方便后续换模型。

* **主要库**

  * 直接使用各家官方 SDK，或 `httpx/requests` 自己写
  * 可选 `langchain` 的 LLM 封装
* **参考项目**

  * 多模型可配：`curiousily/ragbase`（配置化选择模型）
  * OpenAI + LangChain 调用套路：几乎所有前面列的 RAG 项目
* **缝合方式**

  * 定义一个类：

    ```python
    class LLMService:
        def embed(texts: List[str]) -> List[Vector]: ...
        def chat(messages: List[dict]) -> str: ...
    ```

  * 内部通过环境变量决定调用谁：

    * `PROVIDER=openai | moonshot | baichuan`
    * `EMBED_MODEL=...`
    * `CHAT_MODEL=...`
  * 向量模块只调用 `embed`，RAG 模块只调用 `chat`，外面都**不知道具体是 OpenAI 还是谁**。

---

## 8️⃣ 模块8：对话上下文管理（History / Memory）

**职责**：维护多轮对话历史，让“接着上一个问题”这种问法能理解。

* **主要库**

  * 快速上手：`langchain.memory.ConversationBufferMemory`
  * 或自己写轻量的 in-memory store / Redis
* **参考项目**

  * 带会话记忆的 RAG 示例：`sidduneraki/Multi-Document-RAG-Chatbot`（简单记忆）
  * 各种 Chatbot + LangChain 示例（用 BufferMemory）
* **缝合方式**

  * 第一版可以直接用 LangChain 的 Memory：

    * 在构造 RAG Chain 时挂上 `memory=ConversationBufferMemory(k=3)`
  * 自己封装成：

    ```python
    class ConversationStore:
        def add_turn(user, question, answer): ...
        def get_recent(user, k): ...
    ```

  * 后面需要多用户 / 持久化时，把内部实现换成 Redis / DB 即可，模块边界不变。

---

## 9️⃣ 模块9：日志 & 评分 / 审计

**职责**：记录每一次问答的输入、检索结果、输出和耗时，支持人工打分。

* **主要库**

  * `logging` 标准库 + `sqlite3` 或 `SQLAlchemy`
* **参考项目**

  * 有较完整 logging 的：`varundineshan/RAG-AI-Document-Chat`
  * 一些“对话历史持久化”的例子：可参考 `curiousily/ragbase` 等
* **缝合方式**

  * 把 RAG 主流程外面套一层装饰器式的 logger：

    ```python
    def log_qa(user_id, question, answer, retrieved_chunks, timings, score=None)
    ```

  * 对齐你的验收需求：

    * 记录：问题、检索片段（含 meta）、模型回答、是否命中Excel、耗时等
    * 预留一个 `score` 字段，给人工/老师后打分用

## 🔟 模块10：前端 UI（先简单，后解耦）

**职责**：给用户一个能上传文件、选模型、聊天、看来源的界面。

* **主要库**

  * 快速版：`Streamlit`
  * 之后可以考虑 React / Vue + 调 FastAPI
* **参考项目**

  * Streamlit + 多文档聊天 UI：`sidduneraki/Multi-Document-RAG-Chatbot`
  * Excel Q&A 简单UI：`Shivvam/rag-excel-local-qwen3`
* **缝合方式**

  * 第一阶段：

    * 基于 Multi-Document-RAG-Chatbot 的 Streamlit 写一个 monolith 前端
    * 但调用你自己拆好的 API 函数（例如 FastAPI 后端）
  * 第二阶段：

    * 把“业务逻辑”全部放到 FastAPI
    * 前端只负责发 HTTP：`/upload`、`/ask`
    * 这个时候你想换 React 也行，换 Gradio 也行，后端基本不用动

## 最后给你一个“缝合路线图”小总结

1. **选母项目**：用 `sidduneraki/Multi-Document-RAG-Chatbot` 作为起点，在其基础上开始“拆模块 + 抽取工具函数”。
2. **先保证文档 RAG 通了**：模块 1,2,4,5,7,10 基本照抄 + 小改。
3. **加入 Excel 能力**：新增模块 3，参考 `RAG_with_xlsx` / `Azure-RAG-XLS-Chatbot` 把 Excel 行段落塞进向量库。
4. **补足来源标注 + 日志**：整合模块 6,9，参考 `RAG-AI-Document-Chat` 的日志和来源拼接方式。
5. **最后做“工程化”**：抽出 FastAPI 后端，前后端分离，Memory 模块、模型调用模块真正独立。
